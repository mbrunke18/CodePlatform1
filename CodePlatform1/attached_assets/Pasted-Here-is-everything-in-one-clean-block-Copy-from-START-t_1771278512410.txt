EXECUTEIQ ENHANCEMENT BUILD INSTRUCTIONS

Add these new features to the existing ExecuteIQ platform to create a powerful entry experience where users describe a past incident and see how ExecuteIQ would have changed the outcome.

OVERVIEW OF NEW FEATURES TO BUILD

1. Incident Analyzer at /incident-analyzer - AI analyzes user's crisis description
2. Playbook Generator at /playbook-generator - Creates custom playbook from analysis

FEATURE 2 PLAYBOOK GENERATOR

Route: /playbook-generator

Purpose: Takes incident analysis and generates complete editable playbook. User can customize triggers, stakeholders, tasks, and thresholds then save or test live.

User Interface:

Header shows playbook icon plus generated name like "Ransomware Response — Multi-Site Protocol" with playbook code badge like #SEC-001 and subtitle "Generated from your incident" with inline edit capability for name.

Four section layout using tabs or accordion on mobile:

TRIGGERS section shows list of 4-6 trigger conditions. Each has checkbox, condition text, edit button, delete button. Add Trigger button at bottom. Example triggers include "Encryption activity detected on 10+ servers" and "Ransom note discovered on any system" and "Security vendor critical alert received".

STAKEHOLDERS section shows table with columns Role, Name, Email, RACI, Tier, Channels. Example rows: CISO with editable name and email fields, Responsible RACI, Tier 1, channels Slack SMS Phone. CEO with Accountable RACI, Tier 1, channels Slack SMS. CTO with Consulted RACI, Tier 2, channels Slack Email. RACI dropdown options are Responsible, Accountable, Consulted, Informed. Tier dropdown options are 1 Immediate, 2 Fast, 3 Informed. Channels is multi-select with Slack, Email, SMS, Phone options. Add Stakeholder button at bottom.

Example rows: 1 Isolate affected systems, CISO, Critical, 5 min. 2 Verify backup integrity, CTO, Critical, 10 min. 3 Initiate legal hold, General Counsel, Critical, 5 min. Drag to reorder capability. Priority dropdown has Critical, High, Medium options. Owner dropdown populated from stakeholders. Add Task button at bottom.

THRESHOLDS section shows pre-authorized decisions with columns Action, Limit, Approver. Example rows: Emergency security vendor, $500K, CISO. External legal counsel, $200K, General Counsel. Customer notification, dash, CEO. Add Threshold button at bottom.

Action bar sticky at bottom on mobile with buttons: Save to Library saves to existing Playbook Library and shows success toast. Test This Playbook is primary teal button navigating to /simulation. Export PDF downloads playbook as PDF.

FEATURE 3 LIVE SIMULATION

Route: /simulation

Purpose: Simulates real playbook activation with notifications going out, acknowledgments coming in, and tasks being assigned all animated in real-time.

User Interface:

Pre-activation state:

Alert banner with red or amber background, warning icon, title "INCOMING: [Incident Type]", description from trigger, timestamp showing current time.

Playbook info card showing playbook name and code, stakeholders count, tasks count.

Optional email input section with label "Want to receive a real notification?" and email input field and helper text "We'll send you exactly what your team would receive".

Large centered activation button labeled "Activate Playbook" with rocket emoji, teal gradient styling.

Active simulation state after clicking activate:

Header bar with left side showing "EXECUTEIQ ACTIVE" with pulsing green dot, center showing playbook name, right side showing large elapsed time counter in 00:00 format updating every 100ms.

Progress bar labeled "Coordination Progress" showing "X/Y stakeholders acknowledged" with animated fill.

Three column layout that stacks on mobile:

Column 1 Notifications with header "Notifications Sent" and send icon. List of stakeholders appearing one by one with animation showing avatar or icon, name and role, channel icons for Slack SMS etc, timestamp when sent, status showing checkmark Sent in teal. Stakeholders appear based on tier with Tier 1 first then Tier 2 then Tier 3.

Column 2 Acknowledgments with header "Acknowledged" and checkmark icon. List updating as stakeholders acknowledge showing name and role, Acknowledged badge in green, timestamp. Stakeholders who have not acknowledged show as Pending with hourglass in amber.

Column 3 Tasks with header "Tasks Assigned" and clipboard icon. List of tasks appearing after acknowledgments start showing priority badge with Critical in red and High in amber, task title, arrow with Assigned to Role, checkmark when assigned.

Live message preview at bottom panel labeled "Latest Notification Sent" showing realistic Slack message mockup with ExecuteIQ bot avatar, message content showing playbook activation, acknowledge button. Updates as each notification goes out.

Completion state after approximately 60 seconds:

Success banner with green background, checkmark, "COORDINATION COMPLETE", total time displayed large.

Results cards showing Coordination Time as 00:58, Stakeholders Aligned as 6/6, Tasks Assigned as 8/8, Estimated Value Protected as $36M+.

Comparison showing Without ExecuteIQ from analysis and With ExecuteIQ with actual simulation results.

Action buttons: Download Board Briefing as PDF, Save Playbook to Library, Schedule Live Drill linking to contact or calendar, Run Another Scenario going back to incident analyzer.

Frontend Simulation Logic:

Configuration object with totalDuration 60000ms, tier1NotifyDelay 2000ms, tier2NotifyDelay 8000ms, tier3NotifyDelay 15000ms, ackDelayMin 3000ms, ackDelayMax 10000ms, taskAssignStart 20000ms, taskAssignInterval 3000ms.

State variables for elapsed time, notified array, acknowledged array, tasksAssigned array, phase as ready or active or complete.

startSimulation function sets phase to active, records start time, starts interval that runs every 100ms. On each tick calculate elapsed time, notify stakeholders based on their tier when elapsed exceeds their delay threshold, schedule acknowledgment after random delay between min and max, assign tasks after taskAssignStart with new task every taskAssignInterval. When elapsed exceeds totalDuration clear interval and set phase to complete.

Backend API: POST /api/send-simulation-notification

Optional but creates powerful wow factor. If user provides email, send real notification.

Request body contains email, playbook_name, simulation_id.

Uses Resend or SendGrid to send actual email that looks like ExecuteIQ notification. Email contains link to acknowledge. When clicked, hits endpoint that emits WebSocket event to update dashboard in real-time.

FEATURE 4 READINESS ASSESSMENT

Route: /readiness

Purpose: 5-question diagnostic revealing gaps in user's current preparedness. Creates urgency by showing what they do not have.

User Interface:

Progress header showing "Question X of 5" with progress bar.

Questions displayed one at a time or scrolling:

Question 1: "If ransomware hit your company right now, who gets the first call?" Text input for name and role. Helper text "Be specific — name and role".

Question 2: "What's their direct phone number?" Phone input. Helper text "Not the main office line".

Question 3: "What are the first 3 actions in your incident playbook?" Three numbered text inputs. Helper text "In order of priority".

Question 4: "Who can authorize a $500K emergency spend without a meeting?" Text input. Helper text "Name and title".

Question 5: "Where is your incident response playbook documented?" Radio buttons with options: Confluence/Notion, SharePoint/Google Drive, Someone's head, We don't have one.

Submit button labeled "See My Score".

Results page:

Preparedness Score shown as large circular gauge or number, score out of 100, color red if below 40 amber if 40-70 green if above 70.

Gaps Identified as list of what is missing based on answers: "No documented first responder", "No direct contact info on file", "No written playbook exists", "No pre-authorized spending thresholds" each with red X icon.

Benchmark comparison text "You're less prepared than 73% of enterprises in your industry" with bar chart showing where they fall.

CTA buttons: "Build Your Playbook Now" going to /incident-analyzer, "Schedule a Consultation" going to calendar link.

Scoring Logic:

Start with score of 0.

Question 1: If answer exists and length greater than 3, add 20 points.

Question 2: If answer exists and contains 10 digits, add 20 points.

Question 3: Count how many of the three action inputs have length greater than 5. Multiply count by 7 for up to 21 points.

Question 4: If answer exists and length greater than 3, add 19 points.

Question 5: If confluence add 20, if sharepoint add 15, if someones_head add 5, if none add 0.

Return minimum of calculated score and 100.

FEATURE 5 WHAT-IF ANALYZER

Route: /what-if

Purpose: Lets users test modifications to a playbook and see impact on coordination time.

User Interface:

Playbook selector dropdown to choose from saved playbooks. Shows playbook summary when selected.

Modification options as checkboxes or cards: "Add board approval step before major actions", "Require legal review on all external communications", "Add regulatory notification requirement", "Remove a tier-1 stakeholder (simulate unavailability)", "Change primary channel from Slack to Email only".

Analyze Impact button.

Results:

Time comparison showing Original as 12 minutes in teal, Modified as 47 minutes in amber or red, Delta as +35 minutes with arrow.

Visual timeline comparison with two horizontal timelines, original is compact, modified is stretched showing delays.

Impact analysis text: "Adding board approval introduces 35-minute delay", "This moves coordination from immediate to delayed category", risk assessment.

AI Recommendation: "Not recommended for time-critical incidents", "Consider: Pre-authorize board for incidents under $X", alternative suggestions.

Action buttons: Apply This Change updates playbook, Discard returns to original, Save as Variant creates new playbook version.

Backend API: POST /api/what-if-analysis

Claude API prompt:

Analyze the impact of this modification to an ExecuteIQ playbook:

ORIGINAL PLAYBOOK:
[insert playbook JSON here]

MODIFICATION:
[insert modification description here]

Calculate and return:
{
  "original_time_minutes": 12,
  "modified_time_minutes": 47,
  "delta_minutes": 35,
  "delay_factors": [
    {"factor": "Board availability", "delay": "20-30 min", "description": "Board members may not be immediately available"},
    {"factor": "Meeting coordination", "delay": "10-15 min", "description": "Scheduling adds overhead"}
  ],
  "risk_assessment": "This modification significantly increases exposure window during critical incidents",
  "recommendation": "Not recommended for time-critical scenarios. Consider pre-authorization thresholds instead.",
  "alternatives": [

    "Designate board delegate for after-hours incidents"
  ]
