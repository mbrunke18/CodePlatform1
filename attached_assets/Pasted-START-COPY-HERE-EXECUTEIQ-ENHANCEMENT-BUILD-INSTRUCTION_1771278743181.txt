Frontend Simulation Logic:

Configuration object:
- totalDuration: 60000
- tier1NotifyDelay: 2000
- tier2NotifyDelay: 8000
- tier3NotifyDelay: 15000
- ackDelayMin: 3000
- ackDelayMax: 10000
- taskAssignStart: 20000
- taskAssignInterval: 3000
- thresholdClearStart: 15000
- thresholdClearInterval: 5000

State variables:
- elapsed: number
- notified: array of stakeholder ids
- acknowledged: array of stakeholder ids
- tasksAssigned: array of task ids
- thresholdsCleared: array of threshold ids
- phase: ready or active or complete
- currentNotification: stakeholder object for live preview

startSimulation function:
- Set phase to active
- Record start time
- Start interval running every 100ms
- On each tick:
  - Calculate elapsed time
  - Notify stakeholders based on tier when elapsed exceeds delay threshold
  - Schedule acknowledgment after random delay between min and max
  - Clear thresholds after thresholdClearStart
  - Assign tasks after taskAssignStart with new task every taskAssignInterval
  - Update currentNotification for live preview
- When elapsed exceeds totalDuration clear interval and set phase to complete

Backend API: POST /api/send-simulation-notification

Request body:
- email: user's email
- playbook_name: playbook name
- playbook_domain: offense or defense or special_teams
- stakeholder_role: role being simulated
- simulation_id: uuid

Uses Resend or SendGrid to send actual email that looks like ExecuteIQ notification. Email content varies by domain. Contains link to acknowledge. When clicked, hits endpoint that emits WebSocket event to update dashboard in real-time.
