## Honest Gaps — Categorized by Risk

**Risk 1: The Database Is a Single Point of Failure**

Shared dev/prod database (Neon, no separation) is the most dangerous thing in the codebase right now. One bad migration in a demo context wipes production data. One accidental `db:push --force` during development ends the pilot. This is the highest-priority technical debt on the board — not because it's likely to break, but because the consequence if it does is catastrophic at exactly the wrong moment.

**Risk 2: No Test Coverage**

Zero integration tests, zero unit tests against routes.ts (8,500 lines). That file is the entire business logic of the product in one place. A refactor, a new feature, or a rushed fix during a live pilot demonstration could silently break the activation flow. You'd find out in the room.

**Risk 3: routes.ts is Approaching Unmanageable**

8,500 lines in a single file is not a code smell — it's a structural risk. As you add pilot-specific features, emergency fixes, or enterprise customizations, the blast radius of any change grows. This file needs decomposition before you have a second pilot customer.

**Risk 4: Seven Orphaned Pages**

/demo-router, /marketing-landing, /one-click-demo, /ai-intelligence-suite, /live-activation-center, /enterprise-metrics, /unified-platform — all routed, none linked. These aren't neutral. They represent either abandoned product decisions or unfinished work. A pilot customer or investor who discovers them via URL will see incomplete or inconsistent experiences. They need to either be wired into navigation with intentional placement, or removed from routing entirely.

**Risk 5: No Error Monitoring**

No Sentry, no structured logging, no alerting. You're flying blind in production. If the signal monitoring loop silently fails, if GPT-4o calls start erroring, if the activation flow breaks mid-pilot — you won't know until someone tells you.

**Risk 6: Manual Deployment Process**

The pre-built dist/ committed to git strategy works, but it requires developer discipline on every single deploy. Forget to run both builds before commit and production serves stale code. No CI/CD means no guardrail against this. For a solo operation this is manageable — for a platform with live pilot customers it is a risk.
