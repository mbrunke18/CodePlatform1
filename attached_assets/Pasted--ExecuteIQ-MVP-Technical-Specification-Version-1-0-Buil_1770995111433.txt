# ExecuteIQ MVP Technical Specification
## Version 1.0 — Build Document for Developers

---

## Executive Summary

**Product:** ExecuteIQ — Strategic Execution Infrastructure
**Goal:** Build MVP that enables ONE real playbook activation with real stakeholder coordination
**Timeline:** 4-6 weeks
**Core Deliverable:** When a trigger occurs, automatically notify stakeholders, assign tasks, track acknowledgments, and display real-time coordination status

---

## 1. Product Overview

### What ExecuteIQ Does
1. **IDENTIFY** — Detect a strategic trigger (initially manual, later automated)
2. **DETECT** — Match to appropriate playbook from library
3. **EXECUTE** — Notify stakeholders, assign tasks, track progress
4. **ADVANCE** — Learn from execution, improve playbooks

### MVP Scope
- 1 integration: **Slack**
- 3 playbooks: Ransomware, Supplier Failure, M&A Day 1
- Manual trigger (admin clicks "Activate")
- Real-time dashboard showing coordination status
- Basic acknowledgment and task tracking

## 3. Database Schema

### Core Tables

```sql
-- Organizations
CREATE TABLE organizations (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name VARCHAR(255) NOT NULL,
  slug VARCHAR(100) UNIQUE NOT NULL,
  slack_team_id VARCHAR(50),
  slack_access_token TEXT,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

-- Users (Stakeholders)
CREATE TABLE users (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id UUID REFERENCES organizations(id),
  email VARCHAR(255) NOT NULL,
  name VARCHAR(255) NOT NULL,
  title VARCHAR(255),
  department VARCHAR(100),
  phone VARCHAR(50),
  slack_user_id VARCHAR(50),
  tier INTEGER DEFAULT 1, -- 1=Critical, 2=Important, 3=Informed
  created_at TIMESTAMP DEFAULT NOW()
);

-- Playbooks
CREATE TABLE playbooks (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id UUID REFERENCES organizations(id),
  code VARCHAR(20) NOT NULL, -- e.g., '#SEC-001'
  name VARCHAR(255) NOT NULL,
  domain VARCHAR(100), -- Security, Operations, M&A, etc.
  type VARCHAR(20), -- offense, defense, special
  description TEXT,
  trigger_criteria TEXT,
  estimated_duration_minutes INTEGER,
  created_at TIMESTAMP DEFAULT NOW(),
  is_template BOOLEAN DEFAULT FALSE
);

-- Playbook Stakeholder Roles (RACI template)
CREATE TABLE playbook_roles (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  playbook_id UUID REFERENCES playbooks(id),
  role_name VARCHAR(100), -- e.g., 'CISO', 'Legal Lead'
  raci_type VARCHAR(20), -- responsible, accountable, consulted, informed
  notification_priority INTEGER DEFAULT 1,
  required BOOLEAN DEFAULT TRUE
);

-- Playbook Tasks (template)
CREATE TABLE playbook_tasks (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  playbook_id UUID REFERENCES playbooks(id),
  title VARCHAR(500) NOT NULL,
  description TEXT,
  owner_role VARCHAR(100), -- Maps to playbook_roles.role_name
  priority VARCHAR(20), -- critical, high, medium, low
  sequence INTEGER,
  estimated_minutes INTEGER,
  dependencies JSONB -- Array of task IDs that must complete first
);

-- Activations (when a playbook is triggered)
CREATE TABLE activations (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id UUID REFERENCES organizations(id),
  playbook_id UUID REFERENCES playbooks(id),
  triggered_by UUID REFERENCES users(id),
  trigger_description TEXT,
  status VARCHAR(50) DEFAULT 'active', -- active, coordinated, resolved, cancelled
  started_at TIMESTAMP DEFAULT NOW(),
  coordinated_at TIMESTAMP, -- When full coordination achieved
  resolved_at TIMESTAMP,
  metadata JSONB
);

-- Activation Stakeholders (actual people assigned)
CREATE TABLE activation_stakeholders (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  activation_id UUID REFERENCES activations(id),
  user_id UUID REFERENCES users(id),
  role_name VARCHAR(100),
  raci_type VARCHAR(20),
  notified_at TIMESTAMP,
  acknowledged_at TIMESTAMP,
  notification_channel VARCHAR(50), -- slack, email, sms
  notification_id VARCHAR(100) -- External ID for tracking
);

-- Activation Tasks (actual tasks created)
CREATE TABLE activation_tasks (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  activation_id UUID REFERENCES activations(id),
  playbook_task_id UUID REFERENCES playbook_tasks(id),
  assigned_to UUID REFERENCES users(id),
  title VARCHAR(500) NOT NULL,
  description TEXT,
  priority VARCHAR(20),
  status VARCHAR(50) DEFAULT 'pending', -- pending, in_progress, completed, blocked
  created_at TIMESTAMP DEFAULT NOW(),
  started_at TIMESTAMP,
  completed_at TIMESTAMP
);

-- Activity Log (everything that happens)
CREATE TABLE activity_log (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  activation_id UUID REFERENCES activations(id),
  user_id UUID REFERENCES users(id),
  action VARCHAR(100), -- notified, acknowledged, task_started, task_completed
  details JSONB,
  created_at TIMESTAMP DEFAULT NOW()
);
```

## 5. Core Flows

### Flow 1: Playbook Activation

```
1. Admin clicks "Activate Playbook" → selects playbook → adds context
   
2. System creates Activation record
   
3. System maps roles to actual stakeholders:
   - Look up playbook_roles for this playbook
   - Find users matching each role (by title/department or explicit mapping)
   - Create activation_stakeholder records
   
4. System creates tasks:
   - Copy playbook_tasks to activation_tasks
   - Assign owners based on role→user mapping
   
5. Job queue processes notifications:
   - For each stakeholder, send Slack DM with:
     - What's happening
     - Their role (RACI)
     - Their tasks
     - Acknowledge button
   
6. Dashboard shows real-time status via SSE
```

### Flow 2: Stakeholder Acknowledgment

```
1. Stakeholder receives Slack DM with "Acknowledge" button

2. Stakeholder clicks button

3. Slack sends webhook to /api/webhooks/slack

4. System:
   - Finds activation_stakeholder record
   - Updates acknowledged_at timestamp
   - Logs activity
   - Broadcasts update via SSE
   
5. Dashboard updates in real-time

6. If all Tier-1 stakeholders acknowledged:
   - Update activation status to "coordinated"
   - Log coordination time
```

### Flow 3: Task Completion

```
1. Stakeholder clicks task in Slack or Dashboard

2. Marks task as "In Progress" or "Complete"

3. System:
   - Updates activation_task status
   - Checks if dependent tasks can now start
   - Logs activity
   - Broadcasts update
   
4. Dashboard shows progress
```

## 9. Real-Time Updates

### Server-Sent Events (SSE) Implementation

```javascript
// Server endpoint
app.get('/api/activations/:id/live', (req, res) => {
  res.setHeader('Content-Type', 'text/event-stream');
  res.setHeader('Cache-Control', 'no-cache');
  res.setHeader('Connection', 'keep-alive');
  
  const activationId = req.params.id;
  
  // Subscribe to Redis pub/sub for this activation
  const subscriber = redis.duplicate();
  subscriber.subscribe(`activation:${activationId}`);
  
  subscriber.on('message', (channel, message) => {
    res.write(`data: ${message}\n\n`);
  });
  
  req.on('close', () => {
    subscriber.unsubscribe();
    subscriber.quit();
  });
});

// When something happens (e.g., acknowledgment)
function broadcastUpdate(activationId, event) {
  redis.publish(`activation:${activationId}`, JSON.stringify({
    type: event.type, // 'stakeholder_ack', 'task_complete', etc.
    data: event.data,
    timestamp: new Date().toISOString()
  }));
}
```

### Client-Side Handling

```javascript
// React hook for real-time updates
function useActivationUpdates(activationId) {
  const [status, setStatus] = useState(null);
  
  useEffect(() => {
    const eventSource = new EventSource(`/api/activations/${activationId}/live`);
    
    eventSource.onmessage = (event) => {
      const update = JSON.parse(event.data);
      // Update local state based on event type
      handleUpdate(update);
    };
    
    return () => eventSource.close();
  }, [activationId]);
  
  return status;
}
```

## Appendix: Key Questions Developer May Ask

**Q: How do we map roles to actual people?**
A: For MVP, admin manually assigns users to roles during setup. Later, we can infer from job titles.

**Q: What if someone doesn't have Slack?**
A: MVP is Slack-only. Mark them as "no Slack" and skip. V2 adds email/SMS.

**Q: How do we handle multiple activations at once?**
A: Each activation is independent. Dashboard shows all active ones.

**Q: What about permissions/security?**
A: MVP assumes all users in org can view all activations. V2 adds role-based access.

**Q: How do we test without disrupting real Slack?**
A: Create a test Slack workspace with dummy users.
