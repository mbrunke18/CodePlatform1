## The Rule

Three architectures — never conflate them:

| Architecture | Center | Use context |
|---|---|---|
| Company (the category) | Enterprise Readiness | Brand, marketing, investor thesis |
| Product (the organizing object) | Strategic Situations | Product copy, UI, sales conversations |
| Technology (the platform) | Readiness OS | Technical descriptions, integration diagrams |

Strategic Situations = entity. Readiness = attribute of the situation. This is the correct direction — systems of record organize around entities, not attributes.

## Canonical Framing

"The first enterprise system of record for Strategic Situations."

This goes in **supporting copy** (below the hero headline), not as the hero headline itself. The hero stays emotional/curiosity-first ("When the Situation Arrives — The Response Is Ready Before the Trigger Fires." is locked per replit.md). System-of-record framing appears in the italic supporting line below the category clarifier.

## Where This Is Documented

- `/enterprise-readiness-language` — public-facing canonical definitions page with three-architecture block
- Homepage hero — italic gold supporting line introduced after category clarifier

**Why:** Converged from a 4-round strategic advisory review. CRM/ERP/HRIS analogy: each organizes around an entity, not an attribute. "Readiness" is metadata on a Strategic Situation, not the organizing object itself.

**How to apply:** Any time copy describes "what Readiness OS is," use the three-architecture frame. Any time the product's primary object is discussed, name it "Strategic Situation." Any time the category is discussed, name it "Enterprise Readiness." Never use "Readiness OS" as a synonym for the category.
